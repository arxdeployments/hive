# Pinned because app/services/push.py subclasses urllib3's HTTPConnection and
# HTTPSConnection and overrides `_new_conn`, which is PRIVATE API. The subclass
# stays valid Python across versions, so if a future urllib3 stops calling that
# method the peer-address check silently stops running — the SSRF guard would be
# gone with no error anywhere. Both arrive transitively via pywebpush, so without
# these lines a resolver update could change them with no source change here.
#
# The pin is not the whole guarantee and cannot be: it stops an UNREVIEWED update
# reaching production, while tests/test_push_ssrf_guard.py is what detects a
# semantic change — it connects to a real loopback listener and asserts the guard
# fires. Bump these two deliberately and let that test decide whether the hook
# still holds.
